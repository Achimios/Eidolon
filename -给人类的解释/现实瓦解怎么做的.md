# 现实瓦解怎么做的（`tools/reality_melt.py`）

> 参考：用户给的那张草坡看海图（天空往下滴、海变成竖条、飞机照飞），同类在 `Projekt_Visual/_参考库/瓦解_真实场景1/2.jpg`、瓦解1–4。只学手法，不学构图。
> 情绪（👤）：现实的破碎化、digital 化、坠入维度空间；像《Control》/ SCP —— **淡定的人那种荒诞感**：破碎是平常的、一直在发生、事不关己。
> 因为是现实 3D 空间，**运动要克制**，但要有失控感。

## 一句话

天、墙、亮的东西（「可碎区」）从某一行开始被往下拉成长条，一列一列长短不一 → 像融化的流苏；里面再按亮度排一下序。人用抠像保护住，流苏从她身后流过。所有长短、位置都随时间**慢慢**变，鼓点只让某几根突然坠一截。

## 两种手法

| 手法 | 做什么 | 参考图里对应 |
|---|---|---|
| ① 列拉伸 | 每列有一个「断点」b 和一个「长度」L。断点下面那一小段（L / S 个像素）被拉长成 L 个像素（S = 拉伸倍数，每几列一组不同） | 云 / 天空被拉成长条往下滴，锯齿流苏 |
| ② 区间排序 | 可碎区里，亮度在 0.22–0.92 之间的竖向连续段，按亮度排序（亮的在上）。太暗、太亮的不动 | 海面变成竖条、天碎成渐变，人和草完好 |

## 哪里碎（遮罩）

可碎区 = 亮度在一个范围里（默认 > 0.18）×（可选）某个色相（比如只碎蓝天）×（可选）你手画的遮罩 × 不是人。
人 = BiRefNet 抠像（外扩几像素），最后盖回最上层。**没有深度模型**：远近不分，只看亮度 / 颜色 / 手绘。

## 为什么不闪（时间相干）

逐帧随机 = 廉价的故障感，这里要的是液体。

- 断点不是随机行，而是「这一列可碎区的第 q 分位」—— 所以断点长在天上、跟着画面走。
- q 和 L 来自**平滑的随机场**：横向是平滑曲线，时间上每 7 秒换一张、中间平滑过渡，整体还在慢慢横漂。
- 可碎区、断点、排序结果都做了时间平均（EMA），源视频里的噪点不会让流苏跳。
- 排序有一个数学上的好性质：段不变时，**输入变一点，排完序的输出最多变同样多**（自检里验了）。闪烁只来自「段的边界」跳动 → 段边界用平滑过的亮度决定，长段再被每列错开的缝切短。
- 量出来（接触表底部的红线 / `.json` 里 `flicker_ratio_total`）：效果区里输出的「抖动」（时间二阶差分）约是源本身的 1.2–2.6 倍；同样素材如果每帧换随机场，是 23–29 倍。

## 驱动

- **有音乐**（`--drive sense --start 歌里秒数`）：张力（慢平均）决定总体拉多长；强起音（威胁 ≥ 0.6、两次间隔 ≥ 1.5 s）在**某一处**让大约一半的几根流苏突然坠一截（0.1 s 坠下，4 s 慢慢缩回）。不推全局。红白黑配色里，刚坠下的那一截是红的，1.2 秒褪掉。
- **没音乐**（实拍，`--drive time`）：总长度跟一条慢曲线走，下坠按随机的稀疏时刻（平均 ~4.5 秒一次）。
- 整段从「已经碎了一半」慢慢涨到全开 —— 一直在发生，不是爆炸。

## 配色

- `cold`：实拍偏冷蓝（深海军蓝 → 冰白的渐变映射，留一点原色）。
- `rwb`：红白黑。灰阶高反差；红只来自原图里本来就红的东西 + 鼓点刚坠下的那一截。

## 想要 X 就调 Y（`--set 名字=值,名字=值`）

| 想要 | 调 | 默认 |
|---|---|---|
| 流苏更长 / 更短 | `length` | 0.50（× 画高） |
| 开场就碎得多 / 从几乎没碎开始 | `melt0` | 0.55 |
| 流苏里看得见更多原画面（不那么「糊成一条」） | `stretch` 调小 | 14 |
| 粗细、长短更乱（更像参考图的锯齿） | `stretch_spread`、`q_fine` 调大 | 0.9、0.16 |
| 断点更靠可碎区上缘（整片天往下挂） | `q_lo`、`q_hi` 调小 | 0.04、0.55 |
| 变化更慢 / 更快 | `field_period`（秒） | 7 |
| 流苏里的纹理流得更快 / 不流 | `flow`（px/s）、`tex_amp` | 22、0.10 |
| 碎的区域更多 / 更少 | `--zone-lo`（亮度下限）；只碎某个颜色用 `--hue 中心,半宽`（0–1，蓝 ≈ 0.6） | 0.18 |
| 只碎我画的地方 | `--hand 遮罩.png`（白 = 可碎） | 无 |
| 人也一起碎 | `--protect none` | birefnet |
| 少一点排序（更多「滴」少一点「条」） | `sort_amt` 调小（0 = 不排序） | 0.5 |
| 鼓点下坠更明显 / 更少 | `burst_amp`、`burst_thr`、`burst_gap` | 0.22、0.6、1.5 s |
| 下坠缩回得更慢 | `burst_tau`（秒） | 4 |
| 往别的方向流 | `--angle`（0 下、90 右、180 上、270 左，任意角都行） | 0 |
| 镜头动得快、流苏跟不上 | `b_ema`、`zone_ema` 调大（更跟手，代价是更抖） | 0.2、0.15 |
| 静帧的推镜头 | `--push 起,止`（缩放） | 1.0,1.10 |

## 命令

```
.venv/Scripts/python tools/reality_melt.py clip --src 视频或图片 --dur 6 --drive sense --start 160 --label 素材名
.venv/Scripts/python tools/reality_melt.py image 图 --t 2 --palettes cold,rwb --out 目录      # 单帧试参
```

输出：`Projekt_Visual/MV_Cant_Kill_Us/样片/现实瓦解/23_现实瓦解_<素材名>_<配色>_vN.mp4` + `_接触表.jpg` + `.json`（不覆盖，自动取下一个版本号）。

## 每版改了什么

- v1：两种手法 + 场 + 遮罩。问题：她轮廓边上被拉出暗条（拉伸采样越过了可碎区）；闪烁 ~3 倍源。
- v2：只取可碎段里的像素；断点 / 排序层做时间平均；排序长段切短；纹理亚像素流动。闪烁降到 1.2–1.3 倍（走廊、静帧）。流苏默认更长。
- v3：冷色改渐变映射（v2 的冷色发闷）；白走廊换到有鼓点的歌段。
