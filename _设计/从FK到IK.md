## 1. 一句话

**FK = 你逐个指定每个关节。IK = 你只给末端位置，求解器算关节。**

今天的软件界面是 FK：一个矩阵要填几十个数，一条曲线要拖几十个关键帧，UV 要一个边一个边地切。
**人和软件的每一次交互，都是在手工做 FK。**

而 AI 是 IK 求解器 —— 而且对**任何**领域都成立，不只对角色的手臂。

推论只有一条，但很硬：

> **能写成 IK 的活，就不该由人做 FK。**

---

## 2. 为什么界面在浪费你的时间

界面不是做得糙，是**它的本质就是低带宽**：把代码翻译成"人手能点、眼能看"的东西，还得每个软件一份。
一个矩阵在 GUI 里是几十个数字框，在 Python 里是一行 `Matrix.Rotation`。
**同一台机器，两条通道，带宽差两个数量级，而那条窄的还要每软件重学一遍。**

更糟的是：**控件不携带它自己的适用条件。**

| 例子 | GUI 里长什么样 | 背后是什么 | 错了会怎样 |
|---|---|---|---|
| 色彩空间 / 预乘 alpha | "打开图片" + 一个下拉框 | 在哪一步 sRGB → scene-linear；alpha 是否预乘 | **看不见**。发灰、黑边，一错全错，整条下游都错 |
| 采样定理 | 一个 "Filter Size" 滑杆 | 像素不是点，是盒；闪烁/摩尔纹/锯齿都是采样率不够 | 你只会一直滑到"看起来顺眼"，不知道为什么 |
| 旋转 | 三个数字框 + 一个转盘 | 四元数、最短弧 slerp、Euler 会万向节锁死 | 你以为"Blender 有 bug" |

⭐ 学界面学不到**适用条件**，学数学才学得到。这就是「通用哲学方法论、数学思想、架构思维」那句的落地。

（UV 也是个好例子，只是它的代价要讲拓扑：球面不可展 → 切开必有割痕 → 保角和保面积不可兼得。
它适合当第二个例子，不适合当开场。）

## 3. 于是通道按「IK 的输入设备」来分

带宽和频率不是原理，是**选设备的依据**：信号的维度要匹配通道数，反馈的紧迫度要匹配延迟。

| 设备 | 带宽 | 延迟 | 干什么 | 谁 |
|---|---|---|---|---|
| 手柄 / 自制控制器 | 低（4 轴，人手约 6；另 2 扳机） | 实时 | 曲线手感、关键帧时序、点面微调、位移旋转 | 👤 |
| 体感（iPhone / 陀螺仪） | 高（6 自由度连续） | 实时 | 拟真相机、载具、复杂肢体、表情 morph | 👤 |
| 语言 → LLM | 高 | 低频 | 矩阵、节点结构、约束、材质图谱 | AI |
| 代码现场生成的滑块 | 中 | 半实时 | 零碎参数、一次性调试面板 | AI 生成，👤 调 |
| 节点画布（Synapsis） | 极低 | 极低 | **意图本身**。思维画布，不细调 | 👤 |

⭐ 为什么手柄不能少：**缓动、跟随、过冲只能在看的时候调**。"第三帧再松一点"这句话里没有可执行信息，
交出去就是无穷轮往返。⚠️ 但都能后期再调 —— 所以**这一层不追求精修**。

⭐ 为什么 Synapsis 不细调：节点图的价值不在操作精度，在**把脑子里说不清的东西摆出来**。
它是思维的外化，输出意图，不输出数值。接入所有软件是对的方向，但精修属于手柄和体感。
（👤：**「Google 的诞生是允许你在世界 web 中导航，而 Synapsis 是帮助你在自我脑海中导航和记录。」**）

⭐ 为什么专用界面只对某些东西成立：Composer 那种（音频合成器）对，因为**流程已经固化了**。
流程没定时，正确形态是"参数表 + 十行代码现场生成一排滑块"，**UI 变成一次性的**，成本才和寿命匹配。

## 4. 「现实 → 数据」是另一根轴，但也是 IK

上面全是 **人 → 机器**。还有一类是 **现实 → 数据**：说不出来就去做一遍，或者搬一个真的过来。
目的同样是**给末端位置**，只是末端位置长在物理世界里。

| 类 | 手段 | 拿到什么 | 代价 / 注意 |
|---|---|---|---|
| **人身上** | 视频 mocap（无标记 HMR / 体模拟合）、ARKit 面部 blendshape、动捕服 | 姿态、表情、手内动作 → 骨骼曲线 | 要 retarget，你和角色的拓扑不一样 |
| **现实物体 / 场景** | 3DGS / NeRF、多图摄影测量（Quixel Megascans 是扫描库） | 真实几何 + 真实材质外观 | **给的是测量，不是资产**：要 retopo / UV / 去光照才进得了流水线 |
| **画面里的结构** | YOLO / 分割 / 跟踪、visual odometry / SfM | 相机动线、物体轨迹、遮挡关系 → 可执行参数 | 单目有尺度不确定性 |

⭐ **第三类最被低估**：它把"我喜欢这段实拍片的运镜"直接变成一条能驱动 Blender 相机的曲线。
学镜头语言就不靠眼睛猜，而是**从参考片里读出真值** —— 这是「符号说真话」用在镜头上。

**一处纠正**：摄影测量 / SfM 和 visual odometry **数学上是同一套**（从图像恢复位姿 + 结构，都是 bundle adjustment），
差别在**在线 vs 离线**和**精度取向**：VO 要实时、相对、够用（漂移下一帧会纠正）；摄影测量要全局一致、绝对尺度、重投影误差最小。

3DGS 再往前一步：拿 SfM 点云当初始，优化成一堆各向异性高斯 —— **辐射场的一种显式表示**。
能实时渲、能编辑，但**不给你 mesh**。所以它进流水线永远要过 retopo，而 retopo 是概念层的活。

⭐ **人身上带宽最高的信号，恰恰是人自己观测不到的**：你看不见自己的姿态、表情、手指的细小动作，只能"感觉"。
所以这部分意图**不借助设备就永远表达不出来**。这解释了为什么体感和动捕不是噱头 ——
它们不是"更方便的界面"，是**把本来无法外化的意图变成机器可读**。手柄只解决"手"，剩下的必须靠身体。

## 5. 锚点 = 末端位置；规则 = 求解器

👤**「记住涌现的自构建基础，我提供情绪和画面锚点，规则涌现画面和运动。」**（`Eidolon/_设计/哲学.md` §1）

对上 IK 之后，这句话变成了工程语言：

- **锚点 = 末端位置**（少数、高信息、人给）
- **规则 = 求解器**（Kuramoto、反应扩散、DLA、沙堆、最优传输、吸引子）
- **中间不手 K** = 不手工指定关节

⭐ 而且 IK 天生有一个性质，正好解释"为什么要靠规则"：**IK 是欠定的**。
末端位置只约束 6 个自由度，剩下的**零空间**里，求解器随便挑一个解。
游戏里膝盖会翻面就是这个原因。

> **零空间怎么填 = 风格。**
> 规则库做的就是"在零空间里按某种偏好挑解"。规则不是生成画面的东西，**规则是欠定时选解的方式**。

---

## 6. 生成模型的病：零空间太大，所以只能抽卡

生成模型不是不会做，是**不知道你要哪个**。它有你想要的一切可能，你给几十个词，落进分布里就是一坨平均值。
抽卡的实质 = **用随机采样去碰一个没被表达出来的意图**。

于是：

> **锚点 = 把意图变成可计算的东西。锚点越多，零空间越小，抽卡次数越少。**

| 锚点级别 | 载体 | 状态 |
|---|---|---|
| 节奏 / 结构 | `感官.json`（拍、小节、onset、动机位置） | ✅ 真值 |
| 剪辑 / 分镜 | Synapsis 时间轴 → `edl.py --synapsis`（**有测试**） | ✅ 通 |
| 运动轨迹 | 手柄录下来的曲线 | ⭕ 能做，没系统化 |
| 空间 / 光影 / 镜头语言 | **Blender 简模打草稿** | ⭕ 最值钱，没开始 |
| 形象 / 画风 | 参考图 + `layer_decomposition` 拆层 + BiRefNet | ✅ 已用 |
| 声音 | song / 分轨 / 人声 f0 | ✅ 已用 |

⭐**闭环**：成品也能回流成锚点。已渲出的整片、某个元素、某段动作，再丢回生成模型当参考做局部优化 ——
**锚点不是一次性输入，是可以迭代收紧的约束。**

## 7. 判断力不能外包（这条是风险，不是原则）

FK 时代，做一千次之后你会长出"这个动作大概要多少帧"的手感。
IK 时代这个直觉会萎缩 —— 而**判断力正是从大量 FK 操作里长出来的**。
于是有个很实的危险：**你没法判断 AI 给的解对不对，因为判断力本身退化了。**

对策不是"多练"，是**留一条手动路径当校准器** —— 和 👤「用户的耳朵是校准器」是同一件事。
判断力也需要维护，不能外包。

## 8. 判据反查（做之前过一遍）

- **§15 两端都没有质感**（👤「质感来自于有审美的信息量」）：纯噪声不可压缩、信息量最大，但每一点各说各的；
  纯装饰几乎能压成一行，是空的。**质感在中间 —— 有结构的信息。** 而且香农的信息量只度量"惊讶"不度量"重要"，
  意义由故事给，信息量负责让意义读得出。
- **可读的层级**：远看一个形，近看一层结构，贴近还有字和数，每走近一步都有奖励，任何距离都不乱。
- **§16 没有绝对静止**（👤「最终画面必然是要伴随整体元素或镜头始终在动的，即使很多时候很缓慢，attention 时刻在变。
  静态的可以作为分解效果展示、看效果用。」）
- **符号说真话**：HUD 写真参数，粒子由真实动力学算。
- **做不到节点里写的意图时，报告差距，别回头改意图去迁就实现。**（👤 `Synapsis/__AI接入手册.md:35`）
