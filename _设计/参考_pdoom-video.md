## 2. 管线
| 环节 | 做法 |
|---|---|
| 音频分析（Python/uv） | Demucs 分轨 → 两个 CTC 声学模型融合做**全曲一次性强制对齐**，Whisper 交叉校验 → 逐词（部分逐音节）时间；`FIX` 字典里手工修正难点，每条都写了「看频谱图哪里看出来的」 |
| 节拍 | 固定速度拍点网格（132.007 BPM），下拍、段落、kick/snare/hat 起音、各分轨包络 → `data/audio.json` |
| 画面 | **TypeScript + three.js（WebGL2）**：全屏 GLSL shader（光线步进 SDF、雕版排线 `hatch/engrave`）+ Canvas2D 图层画字 + GPU 线段批（10 万级发丝线）+ 后期（bloom、halation、色差、颗粒）。17 个场景约 2 万行 |
| 剪辑 | `timeline.ts`：**切点不写死秒数**，写「哪句歌词开始」→ 吸附到前一个拍点 / 最近的下拍。歌一改对齐，剪辑自动跟着动 |
| 渲染 | 每帧是**歌曲时间 t 的纯函数** → 浏览器实时预览 = 离线导出。headless Chrome 出原始帧 → WebSocket → ffmpeg x264。运动模糊 = 每帧多次子采样平均，按 32×32 块**自适应**加样本（静止 12、快速甩镜 324） |

## 3. 他的「体系」
- **TREATMENT.md = 风格圣经**：一句话概念（「末日论文的插图版」）、调性禁令（不要紫青赛博、不要发光大脑、不要代码雨、「不要看起来像 AI 生成的」）、7 色调色板（橙色 signal 是唯一能发光的颜色）、四种字体各有语义（Archivo=歌词的声音，Plex Mono=机器，Cormorant=神谕，单笔字=被笔写出来的字）。
- **卡拉 OK 规则**：每个词恰好在它被唱时亮起，可以提前 0.4 秒淡显，**高亮永远不许跑在人声前面**；每个场景用不同方式把歌词做进画面（被火花写出、骑在曲线上、当 token 打出来、盖章在表格上、`[MASK]` 遮住）——「字是画面的一部分，不是字幕」。
- **母题贯穿**：一个橙色火花拖着线，写第一句歌词→画损失曲线→变股票线→弯成回形针→变成引信→爆炸。P(doom) 数值随歌词升级（0.02→…→0.99→NaN），**在每个场景里用那个场景自己的语言出现**（等高线标注、示波器读数、表格字段）。
- **UI 卡片当道具**：next-token 概率分布条、out-of-office 自动回复、安全评估表 Form 7-B 盖章、Gantt 排期表——都是笑话，数字是编的。
- **多代理分工**：场景表里有 owner 列（A1–A8、B1、lead），ENGINE.md 写给「场景作者」：只许改自己的场景文件，引擎改动找 lead，`--only` 隔离别人坏掉的场景，出静帧后「用 Read 工具**看** PNG」验收。

## 4. 和 Eidolon 对照
**值得学**
- **剪辑锚在内容上，不锚在秒数上**（`cut('There was a sudden drop')` → 吸到拍）。我们的 edl.py 写的是 `m:ss.ss`，换一版对齐就得手改。
- **帧 = f(t) 的纯函数 + 预览/导出同源**：禁 `Math.random/Date.now`，种子随机。我们 tools/ 各脚本各管各的时间。
- **每个母题一个文件，全片共用**（`_motifs.ts`）：火花、面具在每个场景长得一样。
- 风格圣经里的**禁令清单**写得很具体，比「要克制」好用。

**我们已经更强**
- **符号说真话**：他的图表、概率、表格全是装饰性的笑话；我们的 HUD 写真参数、效果背后是真计算。
- **感官层**（感官.json：信息/期待/情绪）——他没有「观众此刻在感受什么」这层，只有歌词和拍点。
- 有生成视频 + 数学效果两条腿；他这支只有代码一条腿（风格统一，但没有人、没有实拍质感）。

**可以直接借鉴（MIT 内）**
- `analysis/align.py` + `ctcalign.py`：CTC 融合强制对齐 + 手工锚点 + 置信度，比纯 Whisper 准（他就是用 Whisper 只做交叉校验）。
- `analysis/analyze.py`：固定速度拍点网格 + 下拍 + 分轨起音。可以对照我们的 `beats.py` / `sense_song.py`。
- `engine/glsl/common.ts` 的 `hatch/engrave` 雕版排线、`util.ts` 的 `keys()` 关键帧和缓动。
- `scripts/render.ts` 的自适应子帧运动模糊思路（我们以后要做程序化画面的运动模糊时可以参考）。

## 5. 下一步建议
**先拿「剪辑锚在歌词 + 吸附拍点」**：给 edl.py 加一种起点写法 `@"歌词片段"`（必要时再加 `→拍` / `→下拍`），底层接一套逐词对齐（可以参考他的 CTC 对齐）。成本小，以后每一支片子都能复用——这是体系的一块，不是某一支片子的技巧。
