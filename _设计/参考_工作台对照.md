# 参考：成熟创作工作台对照（ComfyUI / Kling / OTIO / 调制）（2026-10-27 查）

> 只读官方文档、官方仓库 README、厂商博客，**没装、没下载、没跑**任何东西。
> 【没验到】= 没找到一手来源，或者来源之间对不上。厂商博客（Kling、Runway）算营销口径，不算实测。
> 判据（`哲学.md`）：工具服务于「这一刻她怎么了」。下面每条「建议」都按这个判据筛过：只借能让**快速出样片、可追溯、少返工**的东西，不借「看起来更专业」的东西。

## 〇、最值得做的 3 件事（按 价值 / 成本 排）

| # | 做什么 | 借自 | 价值 | 成本 |
|---|---|---|---|---|
| **1** | **每个样片都带「怎么做出来的」**：出片时写一份同名 `*.配方.json`（命令行、参数、输入文件的哈希、git commit、种子），ffmpeg 再往 mp4 的 `comment` 里塞一份。拿到任何一个样片都能原样重做，或者改一个参数再做 | ComfyUI 把整张 workflow 写进输出 PNG，拖回去就能恢复（含种子） | 高：👤看过的样片不删、按版本攒，越攒越多。现在想知道「v3 和 v5 差在哪」只能翻对话 | 低：一个 `src/recipe.py` 公共函数，各工具出片时调一行。`meta.json` 里已经有 `ran_with`，可以从那里长出来 |
| **2** | **感受器链改成「按依赖 + 内容哈希决定重跑」**：`separate → sense_song → beats → merge_events → sense_voice → sense_expect` 写成一张小依赖表，每步记输入的哈希，输入没变就跳过，上游变了就把下游全标脏 | ComfyUI 的执行模型：从输出节点往回找，输入或参数没变的节点直接用缓存；`IS_CHANGED` 让节点自己报指纹（LoadImage 报文件哈希） | 高：`__Eidolon_详细规则.md` §一 里那串「整个重写会丢 voice」「voice 重算后要重跑 expect」全是手记的顺序，是返工源 | 中：几十行的 make 式调度，不碰各工具内部。⚠️不用装 ComfyUI |
| **3** | **`edl.py export-otio`：剪辑表 / Synapsis 时间轴 → `.otio`**，单向导出，给 DaVinci Resolve 精剪、调色 | OpenTimelineIO（Apache-2.0） | 中：👤要进 NLE 精修时不用对着剪辑表手拉；感官事件可以变成时间线上的 marker | 低：我们的段落只有「开始、素材、入点、速度」，正好对上 Clip + source_range + LinearTimeWarp。约 60–100 行。要 `pip install opentimelineio`（等👤允许），或者手写 JSON 也行 |

⚠️三件都不是「为了体系而体系」：1 和 2 解决的是已经踩过的坑（版本对不上、顺序跑错），3 只在要进 NLE 时才做。**👤还没说要进 Resolve 之前，3 可以不做。**

## 一、ComfyUI

**事实（已核）**
- 许可：**GPL-3.0**（主仓库 `comfyanonymous/ComfyUI`、前端 `Comfy-Org/ComfyUI_frontend` 都是）。→ 当独立程序用没问题，**代码不能抄进我们仓库**（同 osci-render 那条）。
- 执行模型：README 原话的意思是「每次只执行图里变了的部分」。官方自定义节点文档：从**输出节点**往回走；节点的任何输入或控件值变了才算「变了」；`IS_CHANGED`（和执行函数同参数）返回任意值，和上一次比，不同就重跑；返回 NaN = 每次都跑；内置 LoadImage 返回文件哈希。`OUTPUT_NODE = True` 的节点（保存、预览）每次都执行。
- 惰性输入（lazy）：输入标 `lazy`，节点写 `check_lazy_status` 返回「还需要哪些输入」，不需要的分支就不算（例：开关节点只算选中的那一路）。
- 自定义节点接口：类属性 `INPUT_TYPES`（classmethod，required / optional / hidden）、`RETURN_TYPES`、`RETURN_NAMES`、`FUNCTION`、`CATEGORY`、`OUTPUT_NODE`、`VALIDATE_INPUTS`（执行前校验，只拿到常量输入）。注册表 `NODE_CLASS_MAPPINGS`【没在读到的那页里核到，凭记忆】。
- workflow JSON（v1.0 规范）：顶层 `version / state（各种 lastId 计数）/ nodes / links / groups / reroutes / config / extra / models`；node 有 `id、type、pos、size、mode、inputs[{name,type,link}]、outputs[{links}]、widgets_values`；link = `id、origin_id、origin_slot、target_id、target_slot、type`。`models` 字段记模型名 + 下载 URL + 哈希（可复现用）。
- 另有「API 格式」（只有节点和输入，没有画布坐标）用于 `POST /prompt` 提交。两种格式的区分在官方 spec 页里没写，【没验到】一手说明，来自源码镜像和社区。
- 输出元数据：保存的 PNG 里写文本块 `prompt`（API 格式）+ `extra_pnginfo` 的每个键（通常是 `workflow`，UI 格式）。README：把输出 PNG 拖回页面 = 恢复整张图含种子。WebP / 视频 / 音频有没有同样的嵌入【没验到】。
- 队列与历史：`POST /prompt` 进队列、`GET /queue`、`GET /history/{prompt_id}`、`POST /interrupt`、`GET /object_info`（所有节点的输入输出描述）；WebSocket `/ws` 推 `executing / progress / executed / execution_cached`。
- 前端：TS + Vue，画布是 **LiteGraph 的 fork**（`@comfyorg/litegraph`）；子图（subgraph）要前端 ≥ 1.24.3。litegraph 现在是独立包还是已并进前端仓库，来源互相矛盾 →【没验到】。

| 它解决的问题 | 我们现在怎么做 | 建议 |
|---|---|---|
| 改一个参数，只重算受影响的部分 | 每个 `tools/*.py` 自己判断；感受器链的顺序靠文档里的手记（§一 那串箭头） | **学机制**（→ 第 2 件）：依赖表 + 输入哈希，不要节点图 UI |
| 输出自带「怎么做出来的」，能原样重做 | 样片按版本命名、不覆盖；部分工具写 `meta.json`（`ran_with`）、逐帧 `.json`；没有统一格式，也不在 mp4 里 | **直接借做法**（→ 第 1 件）：配方 sidecar + mp4 comment。用我们自己的格式，不用他们的 JSON |
| 节点自己报指纹（`IS_CHANGED`） | 无 | **学机制**：外部输入（原片、分轨、Seedance 下载的视频）用文件哈希当指纹；云生成（花钱的）指纹 = 请求参数的哈希，命中就不再花钱 |
| 惰性分支 | `--t0/--t1`、`--frame`、`--only` 这类开关，各工具自己写 | **我们已够用**：scope_sim 已经做到「任意时刻开始渲结果一致」，比通用惰性求值更贴需求 |
| 队列 / 历史 / WebSocket 进度 | 前台跑命令；长任务后台跑、等通知 | **不需要**（单人单机）。真要并发跑 Seedance 时，「任务 id → 输入 → 输出文件」的历史表值得借，和 claudia 的付费账本合成一份 |
| 节点图界面 | 剪辑真源是 Synapsis 时间轴页；作曲器是 HTML | **不需要**：哲学 §13「人给稀疏的决定」——👤不该去连线。节点图是给调管线的人用的 |
| 本地跑开源模型（深度、抠像、风格迁移） | 云 API（Seedream / Seedance / Tripo / Neural4D）+ 自己的 torch 脚本 | **不需要**作为主干；以后如果要本地 ControlNet / 深度，可以把 ComfyUI 当**外部服务**：我们 `POST /prompt` 一份 API 格式 JSON，拿结果。GPL 不传染（只调接口，不进代码）【没验到实际可行，没跑过】 |

## 二、Kling（可灵）与 Runway

**事实（来自 Kling 官方博客 + DataCamp 教程；营销口径，没实测）**
- **Elements（元素库）3.0**：「角色 / 物品 / 场景」的库，跨项目复用。建一个元素：多张参考图（官方博客说**最多 4 张**，建议正 / 侧 / 背 / 细节；DataCamp 说**最多 3 张** → 两个来源对不上【没验到】）或一段 3–8 s 的单人视频（抽外观 + 动作 + 声音）。可另配 5–30 s 语音当角色音色。
- **Omni 模式**：提示词里打 `@` 弹出元素选择 = 按名字引用元素。
- **Bind Subject**（绑定主体）开关：首帧图里的人锁到元素上；同一面板有「Add end frame」（首尾帧）。
- **多镜头**：一次生成 3–15 s；「Custom Multi-Shot」= 每镜一行提示词 + 时长，**最多 6 镜**。没有真正的时间线 / 故事板 UI，就是一张镜头列表。
- 声音：可以生成对白 / 环境声（中英日韩西五种语言）。价格按秒和分辨率算，带声音更贵。
- Runway Gen-4：官方说「一张参考图」即可跨光照、场景保持角色一致；当前「References」菜单的具体操作【没验到】。

| 它解决的问题 | 我们现在怎么做 | 建议 |
|---|---|---|
| 同一个角色在多个镜头里长得一样 | Seedance：参考图 1–9 张（2.0）/ 1–30 张（2.5）每次手传；Seedream 出图必须带风格参考（memory） | **直接借做法**：建本地「元素」文件夹：`<作品>/元素/<名字>/` 放正 / 侧 / 背 / 细节 ≤4 张 + `元素.json`（名字、一句描述、用在哪些镜头）。生成脚本按名字取图，不再每次手挑 |
| 提示词里按名字引用素材（`@她`） | 「图1 的构图、图2 的光」（Seedream 的写法，按顺序编号） | **学机制**：分镜里写 `@她 @废墟`，脚本展开成参考图数组 + 「图1 是她…」。编号由脚本生成，人只写名字 |
| 首尾帧控制过渡 | Seedance 首帧 / 首尾帧模式 + `return_last_frame` 接下一段（`接口_生成.md`） | **我们已有**，而且尾帧接首帧的链条比 Kling 的 6 镜列表更灵活 |
| 一次出多镜头（镜头间角色一致） | 一镜一次生成，剪辑在 Synapsis / edl | **不需要**：我们剪辑锚在情绪段和拍点上，一次 15 s 里塞 6 镜会把剪辑权交给模型。只在「同一动作的不同角度」这种情况值得试 |
| 角色音色绑定 | Cortana TTS（`pos` 空间定位、`fx`） | **不需要**：我们的声音是原曲 / 作曲器真值，生成视频的声音一律关 |
| 故事板 / 时间线 | Synapsis 时间轴页 = 剪辑真源；情绪大图；分镜接触表 | **我们已更强**：Kling 的「故事板」只是镜头列表，没有拍点、没有情绪轨、没有感官审计 |
| 接 Kling 本身 | 只接了火山方舟（Seedance / Seedream） | 暂不接。Kling 有 API 文档入口，但字段、价格、能否本地 base64 传图都【没验到】。要比画质时 👤先在网页上手试一两镜 |

## 三、OpenTimelineIO（OTIO）

**事实（已核）**
- 许可 **Apache-2.0**（ASWF 项目）。PyPI `opentimelineio` 0.18.1（2025-11-09），有 Windows x64 轮子（CPython 3.9–3.13）。核心是编译的（有平台轮子），纯 Python 回退【没验到】。
- **核心包只带原生格式**（`.otio` / `.otioz` / `.otiod`）；FCP XML、AAF、CMX3600 EDL 等适配器都搬到了独立仓库，要全套就装 `OpenTimelineIO-Plugins`。
- 数据模型：`Timeline`（`global_start_time`、`tracks` = 一个 `Stack`）→ `Track`（视频 / 音频）→ 里面按顺序放 `Clip / Gap / Transition` 或嵌套的 `Stack / Track`。
  - `Clip`：`media_reference`（`ExternalReference` 指文件 / `ImageSequenceReference` 指图片序列 / `GeneratorReference` 指程序生成的东西，如色块 / `MissingReference`）+ `source_range`（从素材哪段剪进来）+ `markers` + `effects` + `metadata`。v2 起一个 Clip 可以挂多个 media_references（`active_media_reference_key` 选当前那个 → 适合「同一镜的草稿版 / 正式版」）。
  - `Transition`：`transition_type`（如 `SMPTE_Dissolve`）+ `in_offset / out_offset`。
  - `Marker`：`name、color、comment、marked_range、metadata`。
  - `Effect`：`effect_name、enabled、metadata`；时间效果 `LinearTimeWarp`（`time_scalar` = 速度）、`FreezeFrame`。
  - 时间：`RationalTime(value, rate)`、`TimeRange(start, duration)`。**每个对象都有 `metadata` 字典**放任意数据。
- Python API：`otio.adapters.read_from_file / write_to_file`（按扩展名选适配器）。
- **NLE 支持**：
  - **DaVinci Resolve**：18.5 起（2023）发布说明写了「用 OTIO 导入导出时间线」。✅可靠度最高。有用户报告 Premiere Beta 26.1 导出的文件路径带前缀、Resolve 20.2 导不进去（是 Premiere 那边的问题）。
  - **Premiere Pro**：**还在 Beta**。Adobe 2024-10 公告，2026-03 社区里 Adobe 员工仍说「还没到发布标准」。支持：片段名、顺序、出入点、多轨、**线性变速**、序列 / 片段 marker；转场、效果、嵌套序列都没提。Remotion 文档说 Premiere 25.6+ 能导入，和 Adobe 自己的说法冲突【没验到】。
  - 正式版 Premiere 的稳路是 **FCP7 XML**（插件包里的适配器）【没验到实际导入效果】。

| 它解决的问题 | 我们现在怎么做 | 建议 |
|---|---|---|
| 剪辑结构在软件之间搬 | 剪辑真源 = Synapsis 时间轴页（`edl.py --synapsis`）；`剪辑表.txt` 纯文字；`edl.py preview` 用 ffmpeg 拼 480p 预览 | **直接借**（→ 第 3 件）：**单向导出**，不做导回。规矩「下游现读上游、不存副本」：`.otio` 是一次性产物，改剪辑永远改 Synapsis，再导一次 |
| 片段 = 素材 + 入点 + 时长 + 速度 | 剪辑表一行 = `开始 素材@入点 [速度]` | 一对一：`Clip(ExternalReference(路径), source_range=入点..入点+时长×速度)` + `LinearTimeWarp(速度)`；`黑` → `Gap`；`文字:` → `GeneratorReference` 或先渲成小 mp4；`图:` → 静帧 Clip（我们的慢推 zoompan 是效果，NLE 里不会有，写进 metadata 或先渲出来） |
| 时间线上的标记 | 感官.json 的事件、情绪段、显影段；审计图上的▼红 | **直接借**：情绪段 → 时间线 marker（名字 = 「她此刻」那一句），显影段 → 红 marker。进了 Resolve 剪辑师一眼看得到 |
| 任意附加数据 | 剪辑表的 `# 备注`；Synapsis 节点属性 | 每个 Clip 的 `metadata.eidolon = {src 原文, synapsis 节点 id, 配方路径}` → 能从 Resolve 里的片段追回我们的节点 |
| 转场 / 效果 | 我们的效果在 Python 里烧进画面，edl 预览「不叠任何效果」 | **不需要**导效果：OTIO 的 Effect 在各 NLE 之间基本不互通（Premiere 只认线性变速）。效果先烧进素材，再导时间线 |

**导出难度估计**：低。段落列表已经是 `(开始, 素材, 速度)`（`read_edl` / `rows_from_timeline`），时长 = 下一段开始 − 本段开始；`resolve(src)` 已经能把素材语法解析成「文件 + 入点」。主要的活：① 帧率统一（我们 24 fps，`RationalTime(帧, 24)`）；② 路径写绝对路径（Resolve 按路径重连素材）；③ 加一条音轨放原曲。可以在 Node / Python 里自检：导出 → `read_from_file` 读回 → 每段时长加起来 = 剪辑表总长（**必须相等的量**）。真进 Resolve 能不能一次重连所有素材【没验到】，要 👤开一次 Resolve 试。

## 四、调制与「能玩的」结构：VCV Rack / TouchDesigner / Ableton Session

只看能对上「调制矩阵」（理念 §二）和作曲器（场景 / 层 / 旋钮 / take）的部分。

**事实**
- **VCV Rack**：一根**多声道线**最多 16 路；单声道信号接到多声道输入时**自动铺到每一路**。**衰减反相器（attenuverter）**= 强度可以是负的（−1…+1）+ 偏移。许可：Rack 本体 GPL-3.0【凭记忆，没核】。
- **TouchDesigner**：CHOP 通道「导出」到参数（参数变绿 = 被驱动），或在参数里写表达式 `op('x')['chan']`。官方建议**从一个 Null CHOP 导出**：上游随便换，下游的绑定不用重连。可以按「通道名 = 路径:参数」**批量绑定**。2017 年后两种方式性能一样。
- **Ableton Session 视图**：格子 = 轨道 × 场景；**Follow Actions**（片段放完后按规则 / 随机跳到同组的另一个片段，场景也能挂）；**启动量化**（按下后等到下一小节 / 拍才切）；可以全局关掉 Follow Actions 方便编辑。片段包络（clip envelope，每个片段自己的自动化曲线）这次没读到手册那章【没验到细节】。

| 它解决的问题 | 我们现在怎么做 | 建议 |
|---|---|---|
| 一个源驱动很多目标，每条连线有自己的强度 | 理念 §二 写了调制矩阵；作曲器里 `macro_rules`：有效值 = v × (a + b × 张力) | **学机制**：每条连线 = `源 → 目标 × 强度（可负）+ 偏移`。负强度很有用：「越紧张越暗」不用另造一个反向的源 |
| 换上游不用重连下游 | `作曲.json` 指针 `当前.txt`；感官.json 字段只增不改名 | **我们已有同一个思想**（Null CHOP ≈ 定稿指针 + 固定字段名）。补一条：矩阵里的源**只引用字段名**（`macros.dirty`、`channels.threat`），不引用某个工具 |
| 批量绑定（按名字） | 无 | **学机制**：矩阵写成一张表（`规则/` 下的 json，作品可覆盖，同剪辑规则的两层合并），一行一条线，不写代码 |
| 一根线带多路（每个物体 / 每层各一路） | `notes[layer=bass]` → 某个物体；层是分开的 | **学机制**：源可以是向量（每层 / 每个分轨一路），接到「一组物体」时一一对应；单路接一组 = 铺到每个（VCV 的规则） |
| 片段放完自动接下一个、按拍切 | 作曲器：场景切换 + 变体「挑」；页面一直循环 | **学机制**：① 启动量化：场景切换、显影开始默认吸到下一小节（和 pdoom「剪辑吸附拍点」同一件事）；② Follow Action 当「挑」的自动版：循环里按概率轮换 3–4 个变体，👤听到喜欢的按一下锁定 → 写进 `picks`。符合「Nirvana 胜过 Mozart」 |
| 片段自己的自动化 | 旋钮曲线是整首的（`macros` 逐帧） | **不需要**现在做：take 录下来就是整首曲线，够用；等出现「同一个 pattern 在不同场景要不同的滤波走向」再加 |
| 整个乐器 / 视觉环境 | HTML 作曲器 + Python 渲染；Python 效果工具 | **不需要**装 VCV / TouchDesigner：它们是给手实时玩的，我们的「真值事件轨 + 离线同源渲染」是它们没有的 |

## 五、哪里我们已经比它们强（别为了像它们而改）

- **真值**：作曲器发出的每个音直接是事件轨，感受器不用猜；ComfyUI / Kling 的输出都没有「这一帧为什么是这样」的语义层。
- **感官层 + 期待审计**（▼红 = 画面没回应）：没有一个工作台会检查「观众此刻在等什么、画面有没有回应」。
- **同源预览 / 导出**：scope_sim「每帧 = 纯函数，可续渲」、作曲器页面 ↔ composer_render 一一对应——ComfyUI 的缓存是为了快，我们的同源是为了**对**。
- **剪辑锚在情绪和拍点上**：Kling 的多镜头只按秒数分。
